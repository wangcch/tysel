# Application release reference

## Build the artifact set

Build for the production operating system and architecture:

```sh
tysel doctor --install
tysel task verify
tysel inspect
tysel build --release --target linux-arm64 --output dist/orders
```

When the requested target differs from the host, Tysel authenticates and caches
the same-version official runtime stub before packaging. Use `--offline` only
after that target runtime has been verified and cached.

| File | Admission purpose |
| --- | --- |
| `orders` | Native executable with the embedded application and manifest. |
| `orders.sha256` | SHA-256 of the executable. |
| `orders.compat.json` | Runtime and package compatibility decision. |
| `orders.sbom.cdx.json` | CycloneDX 1.5 SBOM. |
| `orders.licenses.json` | Runtime component license inventory. |
| `orders.evidence.json` | Index binding the artifact, target, application, compatibility, SBOM, licenses, and runtime inventory. |

Store all six files under the executable digest. Do not rename, edit, or
regenerate one sidecar independently.

## Sign

Create a new private key on the offline signing host. This command refuses to
replace an existing key:

```sh
set -eu
key_path=/secure/offline-release.key
test ! -e "$key_path"
umask 077
openssl rand -hex 32 > "$key_path"
```

The private-key file contract is:

| Property | Required value |
| --- | --- |
| Encoding | UTF-8 text containing exactly 64 hexadecimal characters. |
| Key material | 32 cryptographically random bytes. |
| File type | Regular file, at most 256 bytes including whitespace. |
| Unix permissions | Group and other permission bits must all be unset; `0600` is accepted. |

Inspect its public identity:

```sh
tysel release key-info --key /secure/offline-release.key
```

The JSON output contains `key_id`, `algorithm`, and `public_key`. Add those
values to the release authority's trust policy, then sign:

```sh
tysel release sign dist/orders \
  --key /secure/offline-release.key
```

The command verifies the artifact set before writing
`orders.evidence.sig.json`. Keep the private key outside the repository,
build directory, command logs, and runtime hosts.

## Trust policy

`deploy/trust.json` is deployment-owned input, not a file generated by
`tysel build`. Its shape is:

```json
{
  "policy_version": 1,
  "issued_at_unix": 1788278400,
  "expires_at_unix": 1790870400,
  "keys": [
    {
      "key_id": "64_HEX_CHARACTERS_FROM_KEY_INFO",
      "algorithm": "ed25519",
      "public_key": "64_HEX_CHARACTERS_FROM_KEY_INFO",
      "status": "active",
      "valid_from_unix": 1788278400
    }
  ]
}
```

Replace every example value. `key_id` is derived from the public key; copy
both values from `tysel release key-info`.

| Field | Rule |
| --- | --- |
| `policy_version` | Must be `1`. |
| `issued_at_unix` | Policy issue time in Unix seconds. |
| `expires_at_unix` | Later than issue time and no more than 90 days after it. |
| `keys` | Non-empty and sorted by `key_id`. |
| `algorithm` | Must be `ed25519`. |
| `status` | `active`, `retired`, or `revoked`. |
| `valid_from_unix` | Earliest accepted signature time for the key. |
| `valid_until_unix` | Required for retired keys; optional for active keys. |

Treat the trust policy as authenticated deployment configuration. Retain
revoked-key tombstones and review key rotation as a forward-only policy
change.

## Verify

```sh
tysel release verify dist/orders \
  --trust deploy/trust.json
```

Verification checks:

- the executable and every release sidecar;
- the evidence and signature digests;
- signature algorithm and key ID;
- key status and validity;
- policy lifetime and signature time;
- SBOM and license inventory consistency.

It fails closed for a changed byte, missing sidecar, revoked key, expired
policy, future signature, or inconsistent inventory.

## Verify the deployment target

`release verify` authenticates the target in the evidence, but the deployment
must supply the expected target:

```sh
expected_target=linux-x64
test "$(jq -r '.artifact.target' dist/orders.evidence.json)" = "$expected_target"
```

Use `linux-arm64` for an arm64 deployment. Reject an empty, unknown, or
mismatched value before copying the executable or building an image.

OCI image signing is separate. After building the image, apply registry policy
and record the mapping from image digest to executable digest.

## Release record

Record:

| Input | Value |
| --- | --- |
| Source | Commit and manifest revision |
| Dependencies | Lockfile digest |
| Toolchain | Installed Tysel version |
| Build | Canonical target and command |
| Artifact | Executable and evidence-index digests |
| Container | Base-image and final image digests, when used |
| Signature | Key ID, trust-policy digest, and verification time |

Do not record private keys, secret values, database URLs, OTLP headers, or
provider credentials.

Evidence proves that one executable and its sidecars belong together. It does
not promise byte-identical application binaries from arbitrary build hosts.

## Verification errors

| Error | Required response |
| --- | --- |
| Executable or sidecar digest mismatch | Quarantine the complete set and rebuild. |
| Compatibility report mismatch | Rebuild with one admitted Tysel release. |
| Missing SBOM or license inventory | Reject admission and restore the immutable complete set. |
| Signed target differs from deployment target | Rebuild for the intended platform and architecture. |
| Trust policy expired | Publish a new authenticated forward-valid policy. |
| Signing key revoked | Stop deployments, rotate offline, then rebuild or re-sign retained verified artifacts under policy. |
