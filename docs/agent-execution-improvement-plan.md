# Agent 执行后续改进计划

当前决定是保留已验证的本地优化，先完成最终提交的全量 CI，再推进有明确证据的
下一项。P0–P5.2 的受限应用验证已经结束；后续性能工作不扩展通用 Agent API。
已完成结果、收益与代价见[交接结论](agent-execution-handoff.md)，
测量来源和历史失败见[证据摘要与归档索引](agent-execution-evidence/README.md)。
本文件只维护未完成工作、优先级和验收规则，不追加每轮运行日志。

## 下一优先项

| 顺序 | 工作项 | 当前依据 | 完成条件 |
| --- | --- | --- | --- |
| 1 | 最终提交验收 | 最新本地审查的三个 P2 已修复，未发现新的具体代码缺陷；最终提交全量 CI 尚未通过确认 | 候选提交的全部必需 CI 通过，源文件和制品身份可核对 |
| 2 | 正常限额下 snapshot 启动异常 | 历史一次失败的触发原因未知；诊断丢失已修复，后续成功样本不能排除问题 | 如复现，取得确切制品、阶段、异常栈、CPU/堆与限额观测；用针对性回归验证根因修复，或明确保留未解决风险 |
| 3 | caller 状态维护成本 | schema 成功复用降低 CPU；维护 UPDATE 和宽行读取仍逐请求执行，历史数据增长可能提高成本 | 分离测量各维护语句、行投影、请求量及 native CPU/job，再选择一个候选 |
| 4 | 最终制品性能基线 | 当前性能数据来自各阶段原始制品；后续原生诊断修改了二进制 | 发布或新性能结论需要时，以最终确切制品建立同环境对照，重新验证受影响成本门槛 |
| 5 | 真实业务接入 | 现有流程仍使用开发身份、本地适配器和单调用方/调度器 | 先明确使用方、读写副作用、权限、部署拓扑与服务目标，再单独立项 |

启动风险与具体审查缺陷分开记录：当前代码审查支持“最终提交全量 CI 通过后合并”，
不等于历史启动事件已解决或可以直接发布。不凭故障注入中的低限额错误解释原始
正常限额失败，也不无限追加相同成功样本来替代根因证据。

## caller 下一候选的测量方式

先保持当前成功 schema 复用、原授权读取和三条维护 UPDATE 不变，覆盖不同历史
任务量、并发及排空后的内存。区分 JS 活对象、分配器保留空间和进程 PSS；分别记录
状态请求数、SQLite 调用/耗时、native CPU/job、端到端 p95 与吞吐。

已有长内存对照中，候选峰值为 54.91–57.05 MiB，但一组基线也仅 57.12 MiB。
另外两组基线约 150 MiB，说明高点具有运行间差异。不能把三对样本的中位下降
宣传为普遍收益，不能以高点消失证明泄漏修复。

诊断显示成本集中后，再单独比较窄投影或索引等候选。不要同时叠加维护快路径、
分配器调参和并发调整；不直接恢复已撤回的 P5.1 组合 SQL 优化。查询计划改善或
SQL 次数下降只是机制证据，保留候选仍需端到端成本和正确性验收。

## 后续实验统一规则

1. 固定对照/候选源码、二进制、完整包、环境和存储目标；先声明负载、阈值与
   追加检查规则，再交错运行相邻对照。绑定目录与 Podman 命名卷分别判定。
2. 保持权限、审计、物理尝试预留、原始 deadline、租约、持久化和验收门槛。
   不以降低状态轮询、提高并发或放宽预算隐式改变已有比较。
3. 诊断埋点与最终无埋点成本分开；重算原始样本，保留所有失败与低基线样本，
   不将不同制品、不同存储或不同观测单位的百分比相加。
4. 候选须通过受影响回归及预声明成本门槛。改动影响包或恢复时，用确切包验证
   跨容器恢复和停机备份/还原；不把旧包验收重新标为新包结果。
5. 运行异常、清理失败和最终保存失败均不得报告完成；性能未达标与执行错误
   分开。报告有效不代表性能通过，离线一致性检查也不能证明测量真实性。
6. 完整过程资料写入本地忽略目录或 CI 制品，记录 SHA-256、环境、复现命令、
   状态与保留位置。Git 只维护结论、工具、测试和最小固定 fixtures。

独立报告验证可以在优化 Python 下运行；实际测量入口明确拒绝 `-O`、`-OO` 和
`PYTHONOPTIMIZE`。原子替换保护已完成的 JSON 快照，不提供 fsync 或断电保证。
复现命令和固定测试数据参见[基准工具说明](../benchmarks/agent-triage/README.md)。

## 保持关闭的范围

- O1 报告复算、O2 失败目标清理、O3 采样落盘和 O4 调度优化已经完成本地验证；
  不因整理归档或追加测试重复宣称新性能收益。
- O4.1 的 4→8 并发诊断没有足够吞吐收益来支持显著增长的 p95，不提高默认限额。
- 已保留的 Web API 缓存只共享固定编译字节；不共享租户 JS 对象、权限或任务状态。
- 应用层保持一个 namespace 的原始完整包、一个调用方和一个调度器；不新增自动
  清理历史、热替换制品、在线备份、分布式 fencing 或外部写入 exactly-once 承诺。
- 只有独立真实应用出现重复逻辑，或现有 API 被具体反例证明不足，才重新评估抽象。
  架构边界见 [ADR-011](adr/011-bounded-agent-application.md)。
