Create, verify, run, and package one HTTP service.

## Install

```sh
curl -fsSL https://tysel.dev/install.sh | sh
tysel doctor --install
```

The managed installation includes the Tysel CLI and native runtimes. Rust,
Node.js, npm, and a Tysel source checkout are not required for this path.

## Create and run

```sh
tysel init hello-tysel --yes
cd hello-tysel
tysel task verify
tysel dev
```

`--yes` selects the generated HTTP service defaults. In another terminal:

```sh
curl http://127.0.0.1:3000/hello
```

Expected response:

```json
{
  "message": "Hello from Tysel",
  "path": "/hello"
}
```

Stop the development server with `Ctrl-C`.

For an existing project, another template, JSON manifest, or different package
integration, use the command matrix in
[Projects and configuration](/docs/concepts/projects-and-configuration#choose-the-files-you-need).

## Write a Fetch handler

The generated `src/index.ts` exports a Fetch-style application:

```ts
import type { TyselApp } from "@tysel/types";
import type { TyselEnv } from "../tysel-env.js";

export default {
  async fetch(request) {
    return Response.json({
      message: "Hello from Tysel",
      path: new URL(request.url).pathname,
    });
  },
} satisfies TyselApp<TyselEnv>;
```

`tysel-env.d.ts` is generated from the manifest. After changing permissions,
refresh and validate it:

```sh
tysel types
tysel types --check
tysel check
tysel compat
```

`compat` reports dependency assumptions; it does not replace application
tests.

## Grant a capability

Outbound resources are denied until declared. For example:

```toml
[permissions]
fetch = ["api.example.com"]
secrets = ["API_TOKEN"]
```

The manifest requests authority. The execution profile and deployment policy
can reduce it further. See the
[manifest field index](/reference/manifest#complete-field-index) and
[capability matrix](/docs/capabilities).

## Build one executable

```sh
tysel task release
./dist/hello-tysel
```

The release task runs the generated verification workflow before
`tysel build --release`. The target machine needs only the executable; it
does not need Node.js or `node_modules`.

Application builds target the host operating system and architecture.
Cross-compilation is not implemented.

For a container, build with a complete manifest whose listener is
`0.0.0.0:3000`. See [Container image](/docs/guides/container-image).

## Use in CI

```sh
tysel --error-format json check
tysel compat --json --strict
tysel test --json
tysel build --release
```

Fatal JSON errors are written to stderr. Test and compatibility reports are
written to stdout. See [Production operations](/docs/operations/production)
before deployment.
