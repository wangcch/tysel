# Go Component SDK

Status: **experimental and repository-local**. The Go module currently uses a
workspace replacement rather than a published semantic version. Keep the SDK,
generated bindings, WIT, and Tysel runtime on the same source revision.

## Guest interface

```go
type Handler func(json.RawMessage) (any, error)

func Dispatch(input string, handler Handler) (string, error)
```

`Dispatch` checks input JSON, invokes the handler, encodes its result, and
enforces 1 MiB input, 1 MiB output, and 4 KiB UTF-8-safe error bounds.

## Generated binding adapter

Component Model bindings remain the guest application's responsibility. The
repository fixture uses Bytecode Alliance `componentize-go` and adapts its
generated result type:

```go
package export_wit_world

import (
    "encoding/json"

    component "github.com/wangcch/tysel/sdk/component-go"
    witTypes "go.bytecodealliance.org/pkg/wit/types"
)

func Run(input string) witTypes.Result[string, string] {
    output, err := component.Dispatch(input, func(input json.RawMessage) (any, error) {
        return input, nil
    })
    if err != nil {
        return witTypes.Err[string, string](err.Error())
    }
    return witTypes.Ok[string, string](output)
}
```

The checked-in fixture was generated with `componentize-go` `0.4.1`; generated
`wit_exports.go` is committed so ordinary builds do not regenerate bindings.

Follow [Build a Go Component](/docs/guides/wasm-component-go) for the tested
workflow and [Component capabilities](/reference/component/capabilities) before adding imports.
