---

Status: `partial`. This page is the supported server-side subset, not
the full browser specification. Behavior outside the lists below is not a
contract.

Source of truth: `runtime-js/web-api/compatibility.json`
(`tysel-server-web-subset`, stable).

## Supported

- string, ArrayBuffer, and ArrayBufferView request/response bodies with byte-preserving consumption
- single-use json/text/arrayBuffer consumption
- bodyUsed
- buffered request and response clone
- streamed host request and response bodies
- UTF-8 decoding after byte collection, including split code points and BOM handling
- Tysel response chunk arrays with snapshotted string/ArrayBuffer/ArrayBufferView elements
- lazy ReadableStream body access with locking and disturbance
- Response with a ReadableStream of Uint8Array chunks, native backpressure and cancellation
- Response.redirect and Response.error with immutable headers and clone preservation
- response status range and null-body status validation; status 101 only after tysel.acceptWebSocket
- null-body helpers are repeatable and do not set bodyUsed
- bytes() returns independent Uint8Array bytes with the same body consumption rules as arrayBuffer()

## Not supported

- formData/blob helpers
- streamed request and response clone
- browser cache/credentials/mode semantics

See the [JavaScript API index](/reference/javascript) and the
[npm compatibility guide](/docs/compatibility).
