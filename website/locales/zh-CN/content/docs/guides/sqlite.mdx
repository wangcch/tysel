本指南配置由运行时管理的 SQLite 客户端，执行参数化语句，验证持久化，并将应用数据库与持久事件日志分开。

## 选择稳定路径

持久存储为 `sqlite` 时，受信任的 `service` 执行配置可以使用 SQLite；这也是清单默认值。可部署应用应明确指定路径：

```toml
[app]
name = "sqlite-worker"
entry = "src/index.ts"
profile = "service"

[durable]
store = "sqlite"
path = "./data/application.db"
```

项目命令从清单目录解析相对路径。打包后的可执行文件从进程工作目录解析。运行时会创建缺失的父目录，但生产环境应挂载稳定的可写卷，并设置确定的工作目录。

## 执行参数化 SQL

```ts
await tysel.sqlite.exec(
  "CREATE TABLE IF NOT EXISTS counters (key TEXT PRIMARY KEY, value INTEGER NOT NULL)",
);
await tysel.sqlite.exec(
  "INSERT INTO counters(key, value) VALUES (?, 1) " +
    "ON CONFLICT(key) DO UPDATE SET value = value + 1",
  ["visits"],
);
const rows = await tysel.sqlite.query(
  "SELECT key, value FROM counters WHERE key = ?",
  ["visits"],
);
```

`exec` 解析为受影响行数，`query` 解析为行对象。参数必须是由 `null`、布尔值、有限数值或字符串组成的数组。绝不要把请求值插值到 SQL 文本中。

运行完整的 [SQLite worker](https://github.com/wangcch/tysel/tree/main/examples/sqlite-worker)：

```sh
cd examples/sqlite-worker
tysel config validate
tysel check
tysel run
```

在另一个终端运行：

```sh
curl 'http://127.0.0.1:3000/?key=visits'
curl 'http://127.0.0.1:3000/?key=visits'
```

第二次响应会报告 `value: 2`。停止并重启进程，再次调用，确认该值仍保存在已配置数据库中。

## 运行时行为与边界

当前运行时在整个进程中管理一个 SQLite 连接，通过 mutex 串行化访问，并应用 5 秒的 SQLite busy timeout。多个 JavaScript 工作线程不会创建独立连接池，因此长时间运行的语句会延迟同一进程中的其他 SQLite 操作。

当前固定边界如下：

| 接口项 | 边界 |
| --- | ---: |
| SQL 文本 | 1 MiB |
| 参数数 | 999 |
| 返回行数 | 10,000 |

SQL 操作失败时，Tysel 会尝试回滚打开的事务，使共享连接保持可用。应使用短事务，避免让一个事务跨越无关 HTTP 请求。

`isolated` 执行配置拒绝 SQLite。SQLite 也不同于 Component 文件系统导入；Component 无法通过请求文件系统根目录获得 `tysel.sqlite`。

## 分离应用数据与持久数据

`durable.path` 选择面向应用的 SQLite 能力。如果模块还导出持久处理程序，除非 `TYSEL_DURABLE_SQLITE_PATH` 或 `TYSEL_DURABLE_POSTGRES_URL` 选择其他事件存储，否则 Tysel 会将 `durable-events.db` 放在该应用数据库旁。

两项功能同时启用时，应备份两个文件。恢复时应将其作为一个应用一致性文件集，并在恢复调度器之前遵循[生产存储指南](/docs/operations/production#durable-postgres-backup-and-restore)。

## 生产检查清单

- 使用具有充足可用空间和 inode 容量的持久本地存储；
- 除非已针对确切锁定模式完成部署测试，否则每个数据库只使用一个应用写入方；
- 使用参数化语句并限制响应大小；
- 监控查询延迟、busy 失败、磁盘延迟和文件系统容量；
- 备份应用数据库并测试恢复；
- 工作负载需要远程多宿主协调、更高并发或数据库管理的可用性时，使用 Postgres。

请参阅 [SQLite API](/reference/runtime/capabilities#sql)、[持久配置](/reference/manifest/durable-observability)和[数据能力限额](/reference/limits-and-defaults#data-capabilities)。
