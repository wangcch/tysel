本指南以明确方式公开 Tysel 服务：选择监听器和 HTTP 协议，启用 WebSocket 升级，授予出站目标，并在部署前验证失败路径。

## 前置条件

- 已安装 Tysel，且 `tysel doctor --install` 检查通过；
- 入站 WebSocket 和出站网络访问使用 `service` 执行配置；
- 公网 HTTPS 使用负责 TLS 终止的 Ingress 或反向代理；
- 可选安装 `websocat` 或其他 WebSocket 客户端，用于验证升级。

## 配置监听器

开发期间从回环地址上的 HTTP/1.1 开始：

```toml
[app]
name = "websocket-service"
entry = "src/index.ts"
profile = "service"

[server]
listen = "127.0.0.1:3000"
http1 = true
http2 = false
websocket = true

[permissions]
fetch = ["api.example.com"]
```

`listen` 控制入站流量。`permissions.fetch` 控制出站 `fetch` 和 WebSocket 目标；两项设置互不隐含。只有在容器或主机中确实需要外部访问该端口时，才将监听器改为 `0.0.0.0:3000`。

Tysel 提供明文 HTTP/2（h2c），不提供 TLS。同时启用两个版本时，会在同一监听器上选择协议。仅使用 HTTP/2 的客户端必须预先知道使用 h2c。WebSocket 升级要求 HTTP/1.1：

```toml
[server]
http1 = true
http2 = true
websocket = true
```

应在 Ingress 终止 HTTPS，并在转发 HTTP/1.1 升级时保留 `Connection` 和 `Upgrade`。不能用公开的明文监听器代替 TLS 终止。

## 实现入站 WebSocket

编辑处理程序前，刷新清单限定的能力环境：

```sh
tysel types
```

```ts
import type { TyselApp } from "@tysel/types";
import type { TyselEnv } from "../tysel-env.js";

export default {
  async fetch(request, runtime) {
    const url = new URL(request.url);
    const upgrade = request.headers.get("upgrade")?.toLowerCase();
    if (url.pathname !== "/ws" || upgrade !== "websocket") {
      return Response.json({ websocket: "/ws" }, { status: 426 });
    }

    const socket = runtime.acceptWebSocket();
    socket.addEventListener("message", async (event) => {
      await socket.send(`echo:${event.data}`);
    });
    return new Response(null, { status: 101 });
  },
} satisfies TyselApp<TyselEnv>;
```

只有在处理符合条件的入站 HTTP/1.1 升级时，`acceptWebSocket()` 才有效。已接受的套接字支持文本消息，以及 [WebSocket 约定](https://tysel.dev/reference/javascript/websocket/)中记录的有边界事件接口。

运行完整的 [WebSocket 服务示例](https://github.com/wangcch/tysel/tree/main/examples/websocket-service)：

```sh
cd examples/websocket-service
tysel check
tysel run
```

在另一个终端运行：

```sh
curl -i http://127.0.0.1:3000/
websocat ws://127.0.0.1:3000/ws
```

HTTP 请求返回 `426`；通过 `websocat` 输入的文本会加上 `echo:` 前缀后返回。

## 调用出站目标

白名单只包含主机名，不包含协议、端口、路径或通配符：

```toml
[permissions]
fetch = ["api.example.com"]
```

```ts
const response = await fetch("https://api.example.com/v1/status");
if (!response.ok) throw new Error(`upstream returned ${response.status}`);
```

每个重定向目标都会重新检查。IP 字面量会被拒绝；DNS 由宿主解析；私有地址和特殊用途地址会被拒绝；重定向无法逃逸已声明主机名集合。出站 WebSocket 使用相同白名单，每个隔离实例请求允许一个活动套接字。

## 验证协议与拒绝行为

```sh
# HTTP/1.1
curl --http1.1 -i http://127.0.0.1:3000/

# h2c prior knowledge, when http2 is enabled
curl --http2-prior-knowledge -i http://127.0.0.1:3000/

# Effective profile and grants
tysel inspect
```

还应测试未声明的出站主机名，并确认宿主将其拒绝。不要把主机拒绝错误转换为通用成功响应；应保留有边界的应用错误并记录请求标识符。

## 生产检查清单

- 只在预期网络策略之后绑定外部地址；
- 终止 TLS，并保留 HTTP/1.1 升级请求头；
- 声明确切的出站主机名，并测试重定向行为；
- 根据工作负载设置正文、超时和准入限额；
- 计算并发容量时包含长连接 WebSocket；
- 使用应用自行提供的就绪端点。
