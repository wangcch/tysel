应用此运行手册前，请先在[部署方案选择](/docs/operations/deployment)中确定以可执行文件还是 OCI 产物作为边界。

支持的生产应用目标平台：

| 目标平台 | 操作系统 | 架构 |
| --- | --- | --- |
| `linux-x64` | Linux | x86-64 |
| `linux-arm64` | Linux | arm64 |

构建默认使用宿主目标平台。受管理的 Tysel 安装可以从其他受支持的 macOS 或 Linux 宿主构建这些 Linux 产物：选择 `--target linux-x64` 或 `--target linux-arm64` 后，它会验证并缓存同版本的官方目标运行时。

## 构建准入

在应用项目中运行以下命令：

```sh
tysel doctor --install
tysel config validate
tysel task verify
tysel inspect
tysel build --release --target linux-x64 --output dist/APP
```

只有每一项都通过，才能准入该版本：

| 检查项 | 必需结果 |
| --- | --- |
| 安装 | `tysel doctor --install` 报告一个包含三个二进制文件的有效发行版。 |
| 项目任务 | `tysel task verify` 成功。 |
| 权限 | `tysel inspect` 只包含获批能力。 |
| 目标平台 | `APP.evidence.json` 记录了部署目标平台。 |
| 产物集 | 可执行文件以及校验和、兼容性、SBOM、许可证和验证材料文件均存在。 |
| 签名 | 要求签名时，`tysel release verify APP --trust TRUST.json` 成功。 |
| 健康状态 | 完全相同的产物能在预发布端口启动，且其应用就绪路由成功。 |

将可执行文件及其伴随文件作为一个不可变集合存储。对于容器，在部署记录中将最终镜像摘要与已准入的可执行文件摘要关联起来。请参阅[可复现发布](/docs/guides/reproducible-release)。

## 运行时约定

| 设置 | 生产值 |
| --- | --- |
| 账户 | 专用非特权用户；不共用应用账户。 |
| 产物路径 | 不可变的版本或摘要目录。 |
| 工作目录 | 保持稳定；仅在相对文件系统路径或 SQLite 路径需要的位置可写。 |
| 监听地址 | 清单中的 `[server].listen`；通常位于终止 TLS 的代理或入口之后。 |
| 启动信号 | 日志包含 <code>{"tysel listen <address>"}</code>。 |
| 就绪状态 | 由应用提供、有时限且无副作用的 HTTP 路由。 |
| 关闭信号 | 服务管理器发送其常规终止信号。 |
| 关闭宽限期 | 至少等于应用请求超时时间；默认超时为 30 秒时应设为 35 秒。 |

生产宿主运行打包后的可执行文件，不需要 Tysel、Node.js、npm 或应用源码树。

## 配置与密钥

| 值 | 来源 | 绝不能存放在 |
| --- | --- | --- |
| 清单配置 | 版本化的部署仓库 | 临时修改的宿主配置 |
| 已声明的机密信息 | 服务管理器或密钥管理器 | 清单、CLI 参数、发布产物 |
| PostgreSQL 授权 `NAME` | <code>{"TYSEL_POSTGRES_<NAME>"}</code> | 清单或镜像 |
| 持久执行 PostgreSQL URL | `TYSEL_DURABLE_POSTGRES_URL` | 清单或镜像 |
| OTLP 凭据 | 标准 OTLP 标头变量 | 端点用户信息或查询字符串 |
| 签名私钥 | 离线发布系统 | 运行时宿主、仓库、构建日志 |

设置 `OTEL_SDK_DISABLED=true` 可禁用导出。OTLP 端点必须使用 HTTP(S)，长度不超过 2 KiB，并且不能包含用户信息、查询参数或片段。

只记录部署元数据：

- 源码提交和清单修订版本；
- 可执行文件、验证材料和镜像摘要；
- 目标平台和 Tysel 版本；
- 签名密钥 ID 和信任策略摘要；
- 部署修订版本和时间。

不要记录凭据、连接 URL、标头、SQL、请求正文或机密值。

## 健康检查与关闭

启动：

1. 在非生产端口或金丝雀环境中启动已准入产物。
2. 等待 `tysel listen <address>`。
3. 通过客户端使用的同一代理路径探测就绪路由。
4. 只有探测成功后才接入流量。

就绪检查应只检查服务流量所需的依赖。端到端健康状态请使用外部合成检查；Tysel 不会添加平台健康端点。

关闭：

1. 停止接入新流量和持久任务认领。
2. 发送服务管理器的常规终止信号。
3. 等待配置的宽限期结束。
4. 如果进程仍未退出，请在强制终止前捕获日志和进程状态。

正常关闭时会将 OTLP 提供器中缓冲的遥测数据发送出去，并停止由服务管理的任务执行子系统。

## 持久执行 PostgreSQL 的备份与恢复

生产持久状态请使用 PostgreSQL。SQLite 适用于本地或单写入者存储，并非多副本共享的持久后端。

### 备份

1. 排空所有写入者，或为完整 Tysel 模式创建一个数据库原生的事务一致性快照。
2. 记录源版本摘要、数据库标识和版本、备份摘要以及 `tysel_durable_metadata.schema_version`。
3. 加密备份并限制访问。
4. 按照保留计划测试恢复。
5. 只有持久状态备份完成后才恢复写入者。

备份必须包含所有 Tysel 持久执行表，包括元数据、程序、事件、唤醒、信号、任务锁和统计信息。不要只复制选定的任务行或个别表。

### 恢复

1. 阻止应用流量和持久调度器运行。
2. 恢复完整快照，或恢复到一个时间点。
3. 让同一 Tysel 版本连接到隔离的目标环境并启动。
4. 验证运行时是否接受该数据库模式、程序摘要、代表性回放、信号交付以及唤醒任务的排他认领。
5. 创建恢复后备份。
6. 先准入调度器，再准入应用流量。

对于 SQLite，请停止所有写入者并使用能够保证 SQLite 一致性的备份机制。直接复制正在使用的数据库不能构成恢复方案。

## 升级与回滚

升级顺序：

1. 准入新版本并备份持久状态。
2. 停止旧调度器认领新的持久任务；让活跃租约完成或过期。
3. 在与生产等效的能力和存储上部署一个金丝雀实例。
4. 测试 HTTP、任务分派、持久回放、信号、被拒能力和遥测数据脱敏。
5. 逐步增加流量，同时对比错误、延迟、内存、数据库争用和到期任务的逾期时长。
6. 租约过期/重新认领周期和进程正常重启均成功后，完成发布。

回滚顺序：

1. 停止新版本调度器。
2. 按已验证的摘要恢复此前的不可变产物或镜像。
3. 重复准入、金丝雀和就绪检查。
4. 只有旧运行时不接受当前模式，或应用迁移不可逆时，才恢复升级前数据库。

绝不要编辑 `tysel_durable_metadata`、伪造租约令牌，或在可变标签下重新创建旧镜像。

## 默认容量限制

以下清单默认值是限制，并非容量承诺：

| 限制 | 默认值 |
| --- | ---: |
| 隔离实例内存 | 128 MiB |
| 每轮 CPU 时间 | 50 ms |
| 请求超时 | 30 秒 |
| 进行中请求 | 1,000 |
| 请求正文 | 16 MiB |
| 响应正文 | 16 MiB |
| 应用 PostgreSQL 连接池 | 每个进程最多 4 个连接；与持久执行 PostgreSQL 存储相互独立 |

使用生产请求正文、任务组合、能力、依赖和遥测数据，对完全相同的版本执行负载测试。对所有副本的数据库连接总数进行预算，并为迁移、备份和运维人员预留容量。

## 监控与告警

| 信号 | 告警条件 |
| --- | --- |
| `tysel.http.server.requests` | 持续出现 5xx 错误，或流量意外消失。 |
| `tysel.http.server.duration` | 延迟接近配置的请求超时时间。 |
| `tysel.capability.calls` | 出现意外的 `denied` 结果，或持续出现 `error` 结果。 |
| 进程状态 | 重启循环、强制终止或内存压力。 |
| OTLP 导出 | 流量仍在继续，但收集器导出消失。 |
| PostgreSQL | 可用性、连接池饱和、锁压力、复制延迟、存储空间、距最近一次备份的时间或证书过期。 |
| 持久调度器 | 到期任务的逾期时长增长，或重新认领停止。 |

Tysel JSON 日志会省略查询字符串、标头、正文、SQL、文件系统路径、URL 和机密值。即便如此，仍应限制访问。请使用 span 和日志中的进程本地关联 ID；不要根据用户输入创建指标标签。

有关具体信号和脱敏规则，请参阅[可观测性](/docs/guides/observability)。

## 事件响应

保留产物和验证材料摘要、目标平台、信任策略摘要、部署修订版本、受影响的任务 ID、关联 ID、数据库时间线及脱敏日志。

| 事件 | 第一响应 | 禁止的捷径 |
| --- | --- | --- |
| 签名密钥泄露 | 在经过身份验证的策略中撤销密钥，停止受影响的部署，离线轮换密钥，并为留存且已验证的产物重新签名。 | 为避免部署失败而让密钥保持活跃。 |
| 机密信息泄露 | 在服务提供商处撤销泄露的凭据，创建新的机密信息版本，重启受影响的进程，并在元数据中排查影响范围。 | 将捕获的机密信息或请求正文复制到事件记录。 |
| 数据库中断或争用 | 停止新的分派，保留进程直至租约过期，恢复服务，然后观察受租约隔离机制保护的重新认领和到期任务的逾期时长。 | 使用过期租约令牌完成工作。 |
| 回放或历史记录冲突 | 隔离任务并保留其完整历史记录和程序摘要。 | 编辑事件、序列号或程序绑定。 |
| 隔离实例崩溃或因资源限制终止 | 检查受限的错误元数据和宿主 cgroup 压力；修复工作负载或并发设置。 | 首先放宽 seccomp、Landlock 或能力授权。 |
| 遥测中断 | 使用独立的健康检查和审计日志，恢复收集器，并通过合成请求验证。 | 将 OTLP 凭据加入端点 URL。 |

恢复后，重新运行发布准入和一次持久重启/回放测试，然后再关闭事件。请参阅[调试](/docs/guides/debugging)。
