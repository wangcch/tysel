本页汇总分散在清单、协议和宿主实现中的限额。清单值属于配置约定。标记为**实现边界**的条目描述当前运行时，未来版本可能调整；应用应能处理拒绝情况，不能依赖精确上限。

## 应用默认值

| 设置 | 默认值 | 来源 |
| --- | ---: | --- |
| 监听地址 | `127.0.0.1:3000` | `server.listen` |
| HTTP/1.1 / HTTP/2 / WebSocket | 开 / 关 / 关 | `server` |
| 内存 | 128 MiB | `limits.memory_mb` |
| 每轮 JavaScript 的 CPU 时间 | 50 ms | `limits.cpu_ms_per_turn` |
| 请求超时 | 30,000 ms | `limits.request_timeout_ms` |
| 并发 HTTP 请求数 | 1,000 | `limits.max_in_flight` |
| 请求/响应目标大小 | 16 MiB / 16 MiB | `limits.max_request_mb`、`max_response_mb` |
| 应用 SQLite 路径 | `./data/tysel.db` | `durable.path` |
| 测试超时 | 5,000 ms | `tysel test --timeout-ms` |

单位和验证规则请参阅[清单限额](/reference/manifest/limits)。当前运行时会强制实施 `max_request_mb`、`max_response_mb` 和 `max_in_flight`。缓冲响应超过限额时会在发送响应头之前失败；流式响应的累计正文大小一旦超过限额就会中止。

## 网络与执行配置边界

| 接口项 | 当前实现边界 |
| --- | ---: |
| 出站 `fetch` 正文 | 16 MiB |
| 出站重定向次数 | 20 |
| `isolated` 执行配置 HTTP 正文 | 32 KiB |
| 单个出站 WebSocket | 每个隔离实例请求 1 个活动套接字 |

`isolated` 执行配置的正文上限比默认清单请求限额更严格。多个边界适用时取较小值。

每个 QuickJS 隔离实例还限制为最多 **256 个未完成的宿主 I/O 操作**和 **32 MiB 的原生 I/O 缓冲区计费内存**。排队中、执行中以及已完成但尚未消费的操作共享这一预算。超限提交抛出包含 `host I/O budget exceeded` 的 `RangeError`；超大的完成结果会使 Promise 被拒绝。重试前应消费结果并限制并发。

这些固定实现边界补充 JavaScript 堆限制，不代表整个进程 RSS 或能力内部临时分配的硬上限。已取消操作仍保留额度，直到其完成通知被丢弃。清除定时器会释放回调引用并取消已启动的原生等待；在同一轮执行中被清除的定时器不会提交原生等待。

## 应用任务与 MCP 边界

| 接口项 | 当前实现边界 |
| --- | ---: |
| 每个模块的任务或持久导出数 | 256 |
| 任务/导出名称 | 128 字节 |
| 任务元数据 | 64 KiB |
| 任务输入/结果 | 1 MiB / 1 MiB |
| JavaScript 任务模块源码 | 64 MiB |
| MCP 消息 | 64 KiB |
| MCP 工具数 | 256 |
| MCP 工具名称 | 128 字节 |
| MCP 描述 | 4 KiB |
| MCP 参数 | 32 KiB |

普通任务 broker 的终态输入、元数据和结果最多保留 **60 秒**，同时限制为 **1,024 条记录**和 **8 MiB 的保留内存计费量**。达到数量或字节上限时会提前淘汰最旧记录；超过预算的单条记录不进入历史。淘汰后历史查询返回无记录。活跃任务与历史分开管理；MCP 调用者直接接收结果，即使消费前历史已被淘汰也不受影响。服务工作线程的空闲轮询也会清理过期历史。这一内存策略不改变 Durable 存储保留规则，也不提供持久化幂等保证。

## 持久执行边界

| 接口项 | 当前实现边界 |
| --- | ---: |
| 边界或信号键 | 256 字节 |
| 事件或信号载荷 | 1 MiB |
| 历史 | 10,000 个事件且总计 16 MiB |
| 待处理信号收件箱 | 1,000 个信号且总计 16 MiB |
| 单个持久程序 | 1 MiB |
| 活跃程序目录 | 10,000 个程序，源码总计 64 MiB |
| 保留的完成结果 | 每任务 1 MiB |
| 保留数据清理 | 每批最多 100 个任务、16 MiB 保留载荷，或单个更大的任务 |
| 并发持久轮询数 | 16 |
| 幂等键 | 1–256 个 UTF-8 字节 |
| 保留的带键信号回执 | 每任务 10,000 条；随已完成任务清理而移除 |

已完成程序和历史会保留到显式清理，但不占用活跃目录配额。没有显式完成记录的旧数据仍算活跃。参见[持久任务管理](/reference/cli/tasks#tysel-durable)。

## Component 边界

| 接口项 | 默认值 | 最大值 |
| --- | ---: | ---: |
| Component 产物 | — | 16 MiB |
| 线性内存 | 64 MiB | 64 MiB |
| 执行时间 | 30 秒 | 60 秒 |
| 输入/输出 | 1 MiB / 1 MiB | 1 MiB / 1 MiB |
| 保留的来宾错误 | — | 4 KiB |
| 宿主专用优化元数据 | — | 64 MiB |

限额通常按字节而非 Unicode 字符计算。调用能力前应拒绝或分块处理过大的输入，并且不要向不受信任的客户端直接暴露原生错误消息。
