# Tysel Component SDK

The Component SDKs target the experimental
`tysel:component/task@0.4.0` interface in `../wit/component/task.wit`:

```wit
run: func(input: string) -> result<string, string>;
```

Both strings contain UTF-8 JSON. The host and SDKs reject malformed JSON and
enforce 1 MiB input/output and 4 KiB error limits.

- Rust: use the workspace crate `tysel-component-sdk`, implement `Task`, and
  call `dispatch` from the WIT-generated `Guest::run` implementation.
- Go: use `sdk/component-go`, then call `component.Dispatch` from the `run`
  export generated by Bytecode Alliance `componentize-go`.

Build a Component, set it as the manifest entry, and use the `component`
profile:

```toml
[app]
name = "echo-component"
entry = "target/echo.component.wasm"
profile = "component"
```

```sh
tysel check
printf '{"value":42}' | tysel run
tysel build
printf '{"value":42}' | ./dist/echo-component
```

See the [Rust](examples/rust-echo/README.md) and
[Go](examples/go-echo/README.md) examples for guest build commands.
The public documentation includes complete
[Rust](../docs/guides/wasm-component-rust.md) and
[Go](../docs/guides/wasm-component-go.md) workflows plus the
[Component contract](../docs/reference/component/index.md).

CI builds real Rust and Go Components and invokes both through the same host
contract test. The Go toolchain's WASI imports run under Tysel's restricted
language-runtime profile: no inherited stdio, environment, arguments,
preopened directories, or network access. This ABI is versioned and smaller
than the TypeScript service API; general WASI application compatibility is not
implied.
